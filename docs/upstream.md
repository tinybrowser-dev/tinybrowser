# Upstream bugs

Policy: upstream bugs stay upstream. Our code stays simple; these fail closed as known-fails. Only make fork changes small and self-contained enough that pulling from upstream stays easy; large upstream/fork changes we cannot reasonably fix ourselves stay upstream and are listed under `## Engine and upstream limitations` below. Tinybrowser-owned feature gaps are tracked as GitHub issues. On fork syncs, upstream wins conflicts: take upstream's shape and re-apply the fork patch on top of it, even where the fork had fixed the code the change rewrites — the fork carries fixes upstream has not taken yet, not a competing design.

A `NodeData::is_document_fragment()` predicate next to the variants (blitz@ffec5987) would give every embedder the same answer. Open, handled on our side.
- `blitz-traits`' `RequestKind` has an `Other` variant with no destination, so an embedder that gates requests by destination has to guess what the request is. Today the only unclassified resource a document hands Blitz is an image a style sheet named, and tinybrowser treats `Other` as an image in one exhaustive match (`crates/renderer/src/document/mod.rs`). Blitz classifying what it fetches would delete the guess. Open, handled on our side.
- Fetch's main fetch makes a `no-cors` request whose redirect mode is not `"follow"` a network error before it is sent, but CSP's deprecated `report-uri` delivery requires `redirect mode "error"` on a request it leaves at `no-cors`. Chromium sends the report anyway and refuses a redirect response, which is the CSP intent; tinybrowser does the same (`RequestPolicy::CspReportUri`). Spec disagreement, recorded rather than worked around by changing the request.
- HTML's secure-context environment rule asks only for the top-level creation URL, so by its text an `http:` iframe inside an `https:` page would be secure, and a popup would not inherit its opener's bit. Chromium instead carries the bit in the policy container (`is_web_secure_context` on `PolicyContainerPolicies`), computes it from the document's own URL and its creator's bit at commit, and clones the initiator's whole container for local-scheme documents, which is what WPT `secure-contexts/` enforces for frames and popups alike. tinybrowser now does the same: `protocol::PolicyContainer` carries the bit, and `is_secure_environment(url, creator)` runs once per commit (`crates/secure-context`, `crates/renderer/src/document/mod.rs`). Spec disagreement, recorded rather than followed off a cliff.
- The `style` crate (Servo) does not parse or store `page-break-before`,
  `page-break-after`, `page-break-inside`, `orphans`, `widows`,
  `alignment-baseline`, or the deprecated `outline-color: invert` keyword.
  `PropertyId` rejects those names, so the declaration is dropped at parse and
  a CSSOM read serializes to the empty string. The previous inline-style shim
  echoed the raw attribute text and reported them, which hid the gap: with the
  declaration block as the source of truth, 24 `css/cssom/serialize-values.html`
  subtests now report the empty string a browser without those properties
  would. The modern `break-before`/`break-after`/`break-inside` longhands are
  supported. Open upstream, not worked around.
- The `style` crate generates `content-visibility` only for the Gecko engine
  (`engine = "gecko"` in `style/properties/longhands.toml`), so the Servo
  backend treats the property as unknown: `CSS.supports` answers false, the
  computed value is absent, and no element can be detected as skipping its
  contents. tinybrowser therefore cannot implement `Element.checkVisibility()`'s
  unconditional "an ancestor has `content-visibility: hidden`" step or its
  `contentVisibilityAuto` option (five `css/cssom-view/checkVisibility.html`
  subtests stay red), and Blitz lays out and paints content the property would
  skip. Open upstream, not worked around.
- `blitz-dom` exposes the inline `style` declaration block (blitz@2ee9c1d3d):
  CSSOM serialization, declaration names in specified order, per-property
  value and priority, `cssText` replacement, and `setProperty` with an
  explicit `!important` flag. The renderer's `CSSStyleDeclaration` is a thin
  shell over it. Fixed in fork.
- `blitz-dom` enables `:has()` and `:nth-child(An+B of S)` and invalidates
  their anchors (blitz@f3e1467ad): both parse gates default off in the style
  crate's prefs, and selector matching records the relative-selector anchors on
  the elements themselves, so a restyle for an attribute, child-list, or state
  change hints each anchor's subtree. `:target` reads
  `ElementState::URLTARGET`, which `BaseDocument::set_url_target` sets from the
  document URL's fragment. Fixed in fork. A relative selector argument that
  looks outside the anchor's subtree (`div:has(~ .x)`, `div:has(+ .x)`, and a
  complex `:not()`/`:is()` that spans siblings) still goes stale: Servo's
  invalidation maps record the exact elements whose style depends on the
  change, and this engine has none, so those arguments need that machinery
  rather than an ancestor flag. Open.
- `blitz-dom` paints the default focus ring with `outline-style: auto`:
  the UA sheet's `:focus-visible` rule asks for `auto`, and the paint path
  draws `auto` as a solid ring instead of skipping it. Browsers report `auto`
  for their focus ring, and `css/selectors/focus-visible-017*.html` asserts
  it. Fixed in fork.
- `blitz-dom` matches `:lang()`, `:root`, and `:empty` by the Selectors 4
  rules: `:lang()` reads the nearest `lang`/`xml:lang` ancestor value and does
  basic language-range filtering; `:root` matches only the document element,
  so the top of a detached or shadow tree no longer matches; and `:empty`
  ignores comments, processing instructions, and zero-length text. The
  matcher's `match_non_ts_pseudo_class` had `Lang(_) => false`, so every
  `:lang()` failed even after the DOM-side hooks were implemented. Fixed in
  fork.
- `blitz-dom` decides attribute-name case sensitivity from the document mode
  rather than assuming HTML: `ElementData` carries whether its node document is
  an HTML document, `DocumentMutator::create_element` stamps it from the
  document node, and `HtmlDocument::from_xml` sets the document's mode to XML
  before parsing. Without it, `[title]` matched `TITLE` in XHTML, and the
  naive "walk to the document through the parent chain" version broke detached
  elements, which have no document ancestor. Fixed in fork.
- An `iframe` removal runs the child document's unload steps (`pagehide` then
  `unload`) before destroying its navigable. HTML says the removing steps
  "destroy a child navigable" and that this "happens without any unload events
  firing"
  (<https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element:html-element-removing-steps>);
  Chromium, Firefox, and WebKit all fire them, pages depend on it for teardown
  reporting, and `fetch/api/basic/keepalive.any.js` fails without it
  (<https://github.com/whatwg/html/issues/10194>). We follow the browsers.
- A `WindowProxy`'s `EventTarget` members are addressed by frame identity
  instead of forwarding the target realm's prototype member: that member's
  receiver check rejects a `WindowProxy`, which is not a platform object in the
  calling realm (`incompatible receiver`). Calls made before the target's realm
  starts, or while a queued navigation is replacing its document, are held by
  the writer realm and replayed when the replacement document's realm starts —
  the same model already used for `WindowProxy` writes
  (<https://html.spec.whatwg.org/multipage/window-object.html#windowproxy-set>).

## Engine and upstream limitations

Large architectural ceilings in upstream dependencies that cannot be solved with small, pullable fork patches live here. Tinybrowser-owned feature gaps are tracked in [GitHub issues](https://github.com/tinybrowser-dev/tinybrowser/issues).

### JavaScript engine (`quickjs-ng` / `rquickjs`)
- Bytecode interpreter with no JIT: script-heavy single-page apps run slower than in V8 or SpiderMonkey.
- Strict-mode global assignment target resolution (`put_var`) resolves at store time rather than LHS evaluation time.
- Cross-realm typed array creation (`Response` body methods returning `Uint8Array`/`ArrayBuffer` in the receiver's realm) lacks a safe `rquickjs` API.
- `rquickjs` passes native callback arguments by value (`Ctx`, `Value`, `String`).

### CSS cascade and selector engine (`stylo` Servo backend)
- Gecko-only properties omitted in Servo builds: `content-visibility`, `scroll-margin-*`, `scroll-padding-*`, `display: ruby-text`, `page-break-*`, `orphans`, `widows`, `alignment-baseline`, `outline-color: invert`, `appearance: base-select`, `::picker(select)`, `::picker-icon`, `::checkmark`, and `:filtered`.
- No full sibling-spanning invalidation maps for complex `:has(~ ...)` / `:has(+ ...)` / `:not()` / `:is()` selectors.
- SVG paint servers (`fill: url(...)`) are not fetched (#308).
- CSS Color 4 OKLCH local-MINDE gamut mapping and Oklab gradient interpolation (`color-mix()`, relative colors).

### Layout, shaping, and painting (`blitz-dom` / `blitz-paint` / `taffy` / `parley` / `fontique` / `anyrender_tiny_skia` / `usvg`)
- Headless one-shot PNG/RGBA rasterization only: no GPU acceleration, no continuous compositor/paint loop, and no audio/video media decoding.
- Shadow DOM `<slot>` projection and shadow-scoped stylesheets (#299).
- Non-atomic inline horizontal `margin`/`padding`/`border` spacing in Parley inline layout (#288).
- `position: sticky` layout offset (reports static box position); `sideways-lr` float placement; `transform-style: preserve-3d` fixed containing block hoisting in `stylo_taffy`; empty non-atomic inline fragment boxes.
- Selector state plumbing in `blitz-dom`: `:valid`/`:invalid` and `<label>`-forwarded `:active`; viewport overflow propagation from `<body>` when `<html>` is `overflow: visible`; per-element scroll-container offset API and `Content-Language` metadata setter.
- `anyrender_tiny_skia` does not implement `backdrop-filter` or filter tainting; `tiny-skia` slightly under-covers arc pixels touching the bitmap edge.
- `fontique` cannot alias an already-loaded system font family for `@font-face` `local()` and has no platform `ui-*` generic families.
- `usvg` external SVG `<image>` EXIF orientation and density correction; SVG `<image>` decoded pixel data is not retained on `ElementData`.
- `parley` / `icu_segmenter` writes `ICU4X data error: No segmentation model for complex script: Chinese/Japanese` to stderr during layout without CJK dictionary/LSTM segmentation data.

### HTML parser (`html5ever` / `blitz-html`)
- `blitz-html` sniffs XHTML by substring on `text/html` doctypes and switches to XML parsing.
- Misnested `<table><form>` controls do not inherit the parser's form element pointer.

### Networking, TLS, and process isolation (`hyper` / `httparse` / OpenSSL)
- `httparse` rejects HTTP/1 response header values containing control bytes other than TAB (`0x0B`, `0x0C`, `0x7F`).
- `http::HeaderName` lowercases request header names on the wire.
- TLS uses OpenSSL's fingerprint rather than Chrome JA3/JA4 impersonation.
- No out-of-process iframe (OOPIF) isolation yet.
