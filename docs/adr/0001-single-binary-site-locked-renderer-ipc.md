# Single binary with site-locked, value-only renderer IPC

Tinybrowser ships as one executable that manages profile-locked daemon lifecycle (`start`, `status`, `stop`, `serve`), runs the browser coordinator and CDP/WebDriver (Classic and BiDi) servers, and spawns child `--renderer` processes (`main → {browser, cdp, webdriver}`, `browser → {dial, net, renderer}`). Each renderer process enters an OS sandbox (`Landlock` + `seccomp-bpf` on Linux, Seatbelt on macOS, Job Objects on Windows; opt-out only via explicit `--no-sandbox`), is locked to a registrable site (`cookies::site`), and talks to the browser over a length-prefixed Postcard channel carrying typed values (`Frame`, `Command`, `ServiceCall`) rather than JSON or shared memory, with the browser process acting as the sole trust and I/O boundary.
