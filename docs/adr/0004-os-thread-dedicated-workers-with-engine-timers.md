# OS-thread workers with worker-owned timers on the injected clock

Dedicated and shared workers both run on their own OS threads (`WorkerDirectory`) with independent `QuickJS` runtimes, reference-counted `SharedArrayBuffer` leases (`SharedBufferTable`), and an atomic interrupt flag so `Atomics.wait` parallelism and `Worker.prototype.terminate()` on infinite loops work per spec. Each worker owns its own `TimerQueue` reading the injected `net::Clock` and receives commands and fetch completions (`WorkerCommand::FetchDone`) on a single `mpsc` channel: on a real clock the thread sleeps in `recv_timeout` until its next deadline, and on a manual clock (the WPT virtual-time harness) it publishes its next deadline atomically so the engine advances the shared clock and wakes it via `WorkerCommand::Wake`.
